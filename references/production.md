# 工程与验收

## 运行环境与新工程

需要 Node.js 22+、FFmpeg / ffprobe、Playwright Chromium。先检查当前环境，不重复安装已有依赖。本包仅带代码和锁定依赖清单，不带浏览器、字体、视频或 TTS。

```sh
cd <skill>
npm ci
npx playwright install chromium
node scripts/create-project.mjs --out <新的作品目录>
```

已有 Playwright 可设 `MOTION_PLAYWRIGHT_MODULE` 为其模块入口绝对路径；已有浏览器可设 `MOTION_CHROMIUM_EXECUTABLE` 为 Chromium/Chrome 可执行文件。不把个人电脑路径硬写进技能代码。启动本机服务受到沙箱限制时按宿主权限流程执行，不把权限错误误报成动画失败。

`create-project --template focus` 可生成随包的受箭焦点示例；`--template v02`生成字波与信号示例，预览可切换新动效做对照；默认仍为急信接力。三例均静音。`create-project` 接受不存在或空目录，拒绝非空目标，不提供覆盖选项。`render` 的输出默认保留，确要替换派生输出时才加 `--overwrite`。用新目录保存改版是更便于比较的选择。

## scene.js 接口

```js
export const width=1920, height=1080, duration=180;
export const ready = /* 字体/本地资源加载 Promise */;
export function render(ctx,t) { /* 按绝对秒数绘制完整一帧 */ }
// 可选 audioWav(): WAV 的 Uint8Array 或 base64 字符串；无此接口就是静音。
```

所有素材在作品根目录内、相对路径引用；导出器拒绝网络请求。图像/字体预加载到 `ready`。不能用 Date.now、每帧随机数或累积状态推进动画；随机纹理固定种子并缓存，粒子位置是时间的函数。相机与主体坐标分层。

`history-kit.js` 坐标固定为 1920×1080。其他同宽高比画幅可在 render 开头 `ctx.scale(width/1920,height/1080)`；换纵横比须重新排版。不要只修改 width/height 后宣称已经适配。时间轴源文件只有一份，预览和导出调用相同 `render`。

常用接口：

| 接口 | 用途 |
|---|---|
| `background(ctx,{paper})` | 暗暖/浅纸材质底，确定性细粒度纹理 |
| `resolveTextBeats(contract,SCENES,events)` / `renderTextBeats(ctx,beats,t)` | 从分镜解析并绘制文字入/停/出；详见文字动作参考 |
| `cameraLayer(ctx,camera,draw,{viewport})` | 世界坐标裁切和推拉，屏幕字幕在外层绘制 |
| `sentence(ctx,rows,t,{x,y,size,lineHeight})` | 旧分行分词组接口；新增文字优先使用 text_beats |
| `route(ctx,points,p,{color,width,head})` | 按弧长揭示折线路径，支持信件/水流/军队进程 |
| `pathPoint(points,p)` | 与同一路径一致的主体位置 |
| `terrain(ctx,{x,y,w,h,seed})` | 山脊示意背景，不是地理数据 |
| `station(ctx,x,y,scale,{lit,flag})` | 有屋檐、房体、门窗、侧面的驿站示意 |
| `rider(ctx,x,y,scale,{t,moving,color,letter})` | 可辨马体、腿部相位与骑者；停下时 moving=false |
| `person(ctx,x,y,scale,{color,arm})` | 衣袍人形与交接手臂姿态 |
| `scroll(ctx,x,y,w,h)` / `seal(ctx,x,y,label,p)` | 文书基底与印章；文字证据另行核实 |
| `timeline(ctx,labels,active,layout)` | 时代或流程节点；不要把流程节点冒充年代 |
| `riverSection(ctx,{x,y,w,h,water})` | 水位变化的河道剖面示意，无实测高程含义 |

这些是可组合的起点，不能替代主题建模。虎符、城门、具体河道应按其辨识结构新建或引入有出处的素材，别将驿站改名充当所有建筑。

## 预览、抽帧、导出

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory <作品目录>
# 在浏览器打开 http://127.0.0.1:8765/，完成后停止服务。
node <skill>/scripts/render.mjs --root <作品目录> --out <作品目录>/film.mp4 --frames 2,7,11,15,20,23
node <skill>/scripts/render.mjs --root <作品目录> --out <作品目录>/film.mp4 --fps 30
```

示例抽帧时刻只适用于 24 秒 starter，新片须按实际场景更新。导出保存 MP4、poster 和 render-report；报告包含尺寸、帧数、解码、重复 seek、浏览器错误、音轨状态。原生页面适配另支持 `--page` 及 `READY/DUR/render/CAPTURE` 合同，未采用时无需增加这一层。

随包 HTML 预览当前只播放画面，不播放 `audioWav()`。音频会由导出器写入 MP4；有声项目须播放最终 MP4 核对同步，或为其预览接入音频时钟，不能用静音预览证明音画同步。

长片先分场检查；用同一工程连续时间渲染即可。性能受限时按场输出中间片段，统一 fps、画幅、色彩与音频后拼接，最终仍要完整解码和检查接缝。不需要为了技能化强行引入大型框架。

## 完成交付的证据

1. **内容**：核心 claims 已核对或有准确限定；示意图、原文引用、古今地图清楚区分。样片不冒充完整历史片。
2. **机制**：每个关键动作检查 before / during / after；交接真的换持有人、关门真的阻断通路、水位真的改变空间关系。
   检查实际几何和遮挡：合拢物必须覆盖原开口，运动路径必须穿过允许通行的区域；红叉、状态标签或旁白不能替代这些条件。一个总览视角说不清动作时，改用俯视/剖面或局部特写。
3. **可读性**：正常大小和 390px 宽抽查片头、关键论据和最密集画面；按 shots 中的文字预算检查中文无缺字、主句无遮挡、关键限定与数字可读且有足够稳定停留。分别记录实际字号换算与目视结果。开场完成时间从最终帧实测，不复用计划值。
4. **连续性**：抽查切点前后、片头片尾，无意外空白/重叠/画面跳位；正常速度播放代表片段。回跳到同一时刻像素一致只是确定性检查，不是审美验收。
5. **技术**：ffprobe 实测规格；完整 ffmpeg 解码；报告 errors/blocked 为空。需要声音时验证音轨、时长和句级同步；静音片在交付说明注明。

QA.md 用四行就能说清：实际完成范围、可验证检查、视觉差距、仍待用户评价。不要给“风格相似度 95%”这种没有评估方法的数字。

## 三道量化检查（交用户前必跑）

这三道专治**「不报错、不崩、但观众一眼看出」**的缺陷——
没有异常、没有红字，只是画面里少一块、暗一档、或贴在一起。
**目视不可靠**（1080p 缩到眼睛能看时，80px 与 36px 的差别已不敏感）。

### 1. `check-layout.py` —— 排版叠字 / 出界

```sh
python <skill>/scripts/check-layout.py <抽帧.png> [更多帧...]
```

**判据：文字像素 = 近白 >195 OR 彩度 >22**（`max(RGB)−min(RGB)`）。

⚠️ **判据错了两次，别再退回去**：

| 版本 | 判据 | 结果 |
|---|---|---|
| v1 | 亮度 >195 | 只认近白主字幕，**场景内彩色标注（朱红 145 / 金 180 / 灰 165）全部漏检** |
| v2 | 亮度 >130 | 灰色地形等高线（峰值 185）涌入 → **284 处假问题** |
| **v3** | **近白 >195 OR 彩度 >22** | ✅ 地形线是灰的（彩度 <12），被自然排除 |

**两个已知盲区**（脚本测不出来，必须人工核）：
- **完全重叠**：两行若用同一个 y，像素连成一条带 → 只测出 1 条带，无法两两比较。
  **纪律：场景里有多行标注时，核对它们的 y 是否互不相同。**
- **文字压住图形**（如结论行压塔尖）：图形不是"文字带"，不参与比较。
  用像素定位确认。

**多行间距的实测下限**：32px 字至少 60px 行距；46px 字至少 86px 基线间距；
80px 字至少 136px。注意**图标也要算进去**（王座图标顶与上方文字只差 7px → 贴住）。

### 2. `check-motion.py` —— 画面是否一直在动

```sh
# 先渲染一串连续帧（每 0.5s 一帧，覆盖各场）
node <skill>/scripts/render.mjs --root <工程目录> --out /tmp/m.mp4 --fps 20 --frames 3,3.5,4,...,179
python <skill>/scripts/check-motion.py /tmp/m-
```

**判据：数「|Δ| > 10 灰阶的像素个数」**，<300 判为静止段。

⚠️ **判据同样错了两次**：

| 版本 | 判据 | 结果 | 为什么错 |
|---|---|---|---|
| v1 | 画面区**全局平均**变化量 | 169 个假静段 | 平均被静止部分（墙、地面）稀释 |
| v2 | **最活跃 5% 像素**的均值 | 174 个假静段 | 5% = 6 万像素，实际只动 2–3 千，分母仍太大 |
| **v3** | **直接数 \|Δ\|>10 的像素数** | **0 个静段** | ✅ 数绝对数量，不取分位数 |

> **教训：判「有没有」要数绝对数量，不要取会随分母漂移的分位数。**

**为什么需要这道检查**：动效若都绑在固定窗口（如"烟只在 2.2–4.2s"），
**窗口之间画面变化像素 = 0**，观众感觉"画面死了、只有文字在动"。
> 修法：把一次性动效改成**循环持续**，并加一层贯穿全片的**尘埃层**（强度压到 alpha≈0.2）。

### 3. `check-timing.py` —— 动画时刻是否超出场长

```sh
python <skill>/scripts/check-timing.py --root <工程目录>
```

**判据：每场内所有 `phase(t,a,b)` 的 b ≤ 该场场长**（带 `i*Y` 偏移按 i 最大 2 算）。

⚠️ **这是本项目最隐蔽的一类缺陷**：
把片长从 210 秒压到 180 秒后，S03 的卡片写着 `phase(t,45,47.5)`，
而 S03 只有 42 秒 → `ease(phase(...))` **恒为 0**，**这张卡片永远不会出现**。
观众看到的是"第三份资料还没显示就跳走了"。

> **纪律：任何改动场长 / 句子时刻 / 分镜顺序之后，立刻复跑本检查。**
> 同类问题还抓到两处：S01 空路提示永不淡出、S04 朱红叉没画完（差 1.6s）。

## 画面观感的量化口径

### 「画面显得空」怎么量

不要凭感觉。**按纵向分带测内容占比**，并与参考片**同口径对比**：

| 纵向带 | 本片（修前） | 参考片（字波档） |
|---|---|---|
| y120（字幕行） | 3.6–7.5% | 11–13% |
| y240–600（主体） | **0–2.6%** | 0.1–7.7% |
| y600–1080（下部） | 0–1.4% | 0–2.7% |

实测发现：**下部留白与参考片同构，不是缺陷**；
真正的问题是**画面主体位置偏低**（我的元素在 y780–950，参考片在 y480–720），
导致中间一条是空的。→ 整体上移约 120px 后观感改善明显。

### 新元素可辨识度怎么定

**渲一帧按实际尺寸看**，不能只按坐标推算。
实测：骑兵 `scale=0.62` 时每骑约 40px，全屏下认不出是"兵马"；调到 0.92 才可辨识。

## ⭐ 压缩片长时的「换句窗口」（本轮实测踩到的坑）

把片长从 180s 压到 115s 时，只压了**句间空档**（0.6→0.22s），
结果**换句瞬间出现两句叠字**——同一行位置上前句的残影与后句重影。

### 根因：入场是**逐字**的，实际耗时 ≠ `entry.duration`

```
整句入场实际耗时 = entry.duration + entry.stagger × (字数 − 1)
```

实测：`duration 0.42 + stagger 0.01×8` = **0.50s**，
而原来的换句窗口是「出场 0.28 + 空档 0.22 = 0.50s」——**刚好卡在边界**，
于是后句第一个字入场时，前句最后一个字还没退干净。

### 判据（务必满足）

```
出场时长 + 句间空档  >  最长句的「整句入场实际耗时」+ 余量(≥0.10s)
```

**本片最终参数**（120 秒版）：
```
入场  duration 0.24–0.26 ｜ stagger 0.004–0.005   →  最长句整句入场 0.36s
出场  duration 0.20
空档  0.34s
→ 换句窗口 0.54s，余量 0.18s ✅
```

### 附带纪律

**只压空档不压入场动画 = 一定会叠字。** 两者必须一起改。
片长压缩后要**专门渲染所有换句时刻**（每个 `(前句end + 后句start)/2` 取一帧）跑
`check-layout.py`，不能只抽查几个。

```python
# 生成所有换句危险时刻
pts = []
for sh in shots:
    for i in range(len(sh.text_beats)-1):
        mid = (sh.text_beats[i].end + sh.text_beats[i+1].start)/2
        pts.append(sh.start + mid)
```

### 另外：压缩片长会让**画面元素挤到一起**

S05 压缩后，三个标注（「幽王的弟弟」「二十一年后被杀」「九年，天下没有王」）
和王座图标挤在 y668/760/800/938 —— 视觉上糊成一块。
`check-layout.py` 的「x 不交叠就跳过」规则抓不到这类，
现已补一条 **`💡 元素过近`** 提示（水平隙 <40px 且垂直隙 <12px）。

## ⭐ 第四道检查：运行时文字重叠（`check-overlap-live.py`）

前三道都治不了**「元素颜色偏暗时的重叠」**——因为像素法过不了亮度阈值。
本轮实测：地图 13 个标注，`check-layout.py` 报 0 问题，**实际有 2 处重叠**。

### 做法：逐帧真的调一次 `render()`，读回实际绘制的文字坐标

```sh
python <skill>/scripts/check-overlap-live.py --root <工程目录> --step 1.0
```

原理：`history-kit.js` 的 `text()` 与 `scene.js` 的 `mid()` 里挂了一个记录钩子，
把每次调用的 `(文本, x, y, 字号, align)` 推进 `TEXT_LOG`（成片不受影响）。
检查脚本用 Playwright 驱动页面，设 t → 调 render → 读 TEXT_LOG → 按包围盒两两比对。

**实测效果**：119 帧 / 553–603 个文字元素，**一次跑完 20 秒内**，
抓到本轮全部 6 处真重叠（S02 三处、S04 两处、S01 一处）。

### ⚠️ 三个前提（缺一不可）

1. **`history-kit.js` 必须有 `TEXT_LOG` 钩子**（本技能已内置）
2. **`scene.js` 要 `export {TEXT_LOG}`**
3. **`index.html` 要在 `await scene.ready` 之后**再设
   `window.__scene = scene; window.__sceneReady = true;`
   —— 顺序反了会拿到未加载完的底图，检查结果不可信

### ⚠️ 它**只查文字 vs 文字，不查图形压文字**

图形（竹简、墓室框、火）压住文字，它测不出来。
**图形占位要用「坐标区间手算」**，逐场列出每个图形组的 y 范围，
与字幕区（基线 y930 / 80px → 盒 y866–944）比对。

本轮就是这么发现 **S02 的简排到 y926、撞进字幕区**的。

### 纪律：画面里元素多的时候，四道检查都要跑

| 检查 | 治什么 |
|---|---|
| `check-layout.py` | 排版叠字（像素法，亮色元素） |
| `check-timing.py` | 动画时刻越界 |
| `check-motion.py` | 画面是否一直在动 |
| **`check-overlap-live.py`** | **文字重叠（运行时，暗色元素也抓）** |
| 坐标手算 | **图形压文字 / 图形压字幕** |

### ⭐⭐ 铁律：**同屏只讲一件事**（S02 与 S06 都栽在这上面）

**两次实测事故**：

| 场 | 我干了什么 | 后果 |
|---|---|---|
| S02 | 「墓室剖面」「喜」「竹简铺开」三组**同时**画在画面中央 | 糊成一团 |
| S06 | 「左萧何／右项羽」分屏 **+** 中间「失期法皆斩」大字 **+** 一条贯穿全屏的竖分隔线 | 大字压着火堆与人物；竖线从大字中间穿过（用户截图指出） |

**正解：把一场切成 2–3 个节拍，每个节拍只讲一件事。**

```js
// 每组元素：进场淡入 × 退场淡出
const a  = ease(phase(t, 进场起, 进场止));
const ao = 1 - ease(phase(t, 退场起, 退场止));
const an = a * ao;
if(an > 0.01) layer(g, an, () => { /* 只画这一组 */ });

// 两组之间留 0.4–0.8s 的空档，让上一组退干净
```

S02 的节拍：
```
节拍1  0.6–6.0s   墓室剖面
节拍2  7.0–12.4s  「喜」独占
节拍3 13.4–21.0s  竹简铺开
```
S06 的节拍：
```
节拍1  1.2–7.0s   左萧何 / 右项羽（分屏对比，分屏线只画上半段）
节拍2  7.4–11.2s  只剩「失期法皆斩」（左实右虚 + 朱红中缝）
节拍3 11.8–18.0s  那枚简 +「喜」收尾
```

### 附带三条版面纪律

1. **分屏线不要贯穿全屏**——只画有信息的那一段（S06 原来画 y160–880，
   正好从大字中间穿过）。
2. **标注要避开底图上本来就有的主体**（S06 的「萧何」压在底图人物身上）。
   写实底图上叠矢量标注时，先看清底图的主体在哪。
3. **成对说明分列中线两侧**，不要挤在一起（「没法证实／没法证伪」）——
   间距 ≥ 400px 才读得清。

## ⚠️ 我第三次犯同类错误：批量改源码文字，改坏语法

**这次的错误**：把 `str:` 批量改成 `amp:` 时，同一条 `re.sub` 把
**对象字面量里的 `rgb='...'` 也套用了「解构默认值」的写法**——

```js
// ❌ 对象字面量里不能用 = （这是「默认参数解构」的语法）
fxPulse(g,t,EV.X,{win:0.5,rgb='218,164,72',amp:.09});
// ✅ 对象字面量必须用 : 
fxPulse(g,t,EV.X,{win:0.5,rgb:'218,164,72',amp:.09});
```

报错是 `Invalid shorthand property initializer`——**不报行号**，
排查花了很久（试了 5 种定位手段都失败）。

### ⭐ 定位这类错误，唯一可靠的办法：**逐行单测可疑片段**

```js
const vm=require('vm');
// 把可疑的语句单独拿出来编译，看哪一句报错
new vm.SourceTextModule("f(1,2,y,{win:0.5,rgb='1,2,3',amp:.08});")
// → Invalid shorthand property initializer  ← 立刻定位
```

**比二分法、从尾删、逐场剥离都快**——因为它是**逐语法单元**测，不受
「截断后函数不完整」的干扰（那三种方法我都试了，全被这个干扰骗了）。

### 三条累计教训（同一个根：**批量文本替换**）

1. 正则改坐标 → 误伤颜色值、数组语法、小数值（详见上文）
2. 正则改坐标 → 把 `fillRect(0,0,W,H)` 改成 `(60,120,W,H)`
3. 正则改字段名 → 把对象字面量的 `:` 改成 `=`

**统一纪律**：
- **不要用正则批量改源码。** 要改就**显式重写整个函数**。
- 若必须批量改，**改完立刻 `import()` 验证一次**，并在**同一批次内**做——
  不要等到渲染超时才发现。
- 报错**不给行号**时，用 `new vm.SourceTextModule(可疑片段)` **逐句单测**。
