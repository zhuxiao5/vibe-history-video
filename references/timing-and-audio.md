# 节奏、文字与共享时间表

v2 从 72 秒《草船借箭》工程提炼流程：提早出现完整观众问题，关键证据按手机尺寸排版，分场与声画事件由同一来源驱动。该工程是案例，不是史料校验和审美的通用答案。

## 字速基准（默认值）

**台词时长 = 字数 ÷ 字速**，不是凭感觉给。

| 类型 | 字速 | 单句下限 |
|---|---|---|
| 白话句 | **5.0 字/秒** | 2.2 秒 |
| 文言引文 | **4.4 字/秒** | 2.2 秒 |

**片长推算**：
```
片长 ≈ 字数 ÷ 5.0 + 换句处数 × 0.34 + 场数 × 0.56
```
实测对照（《烽火戏诸侯》120 秒版）：37 句 / 499 字 / 6 场 →
499÷5.0 = 99.8s ＋ 31×0.34 = 10.5s ＋ 6×0.56 = 3.4s → **113.7s**（实际 120.0s，
差额来自 8 句引文按 4.4 字/秒算、以及 6 句短句触 2.2s 下限）

**换句交接（必须一起设）**：
```
句间空档 0.34s ｜ 场首末 0.28s
入场 duration 0.24–0.26 ｜ stagger 0.004–0.005 ｜ blur 3–4
出场 duration 0.20      ｜ stagger 0.007
```
> ⚠️ 入场是**逐字**的：整句耗时 = `duration + stagger × (字数−1)`。
> 判据：**出场 + 空档 > 最长句的整句入场耗时 + 0.10s**。
> 只压空档不压入场 → 换句瞬间两句叠字。

详见 [工程与验收](production.md) 的「压缩片长时的换句窗口」。

## 先定合同，再做最难一段

从 `assets/contracts/shots.example.json` 复制合同到作品。填写准确的问题、关键论据和 before/action/after；示例文字不可直接交付。主句出现得快不等于观众已经读完，另留完整显示后的稳定停留。让代表段同时覆盖开场或关键文字和最难机制，按实际镜头选择 12–30 秒；不为了测试把整片重做。

渲染前先跑 `python <history-video>/scripts/check-contract.py --shots <作品>/shots.json`，它只核对计划时限、字号预算和停留字段，不把计划当实测通过。

手机字号预算公式：`画布字号 × 展示宽度 / 画布宽度`。1920 宽画布中 84px 在 390 宽下约 17.1px，29px 约 5.9px；这只是字号投影，不是实际字高测量。核对最终 MP4 缩图，不能只看浏览器放大后的文本。证据太多时拆单卡，缩短准确摘句，完整材料留事实表。关键范围限定必须进入可读主句。

船体等机制须分清基础机制值与装饰晃动：标签由阶段与真实机制状态共同决定，不能仅凭某一帧倾角报“回正”。转向要检查中间帧，必要时增加俯视小窗，避免缩放过零使主体消失。示意与实际几何复原的边界在 QA 中写清楚。

## 一份时间表

无声且简单的工程可保留 scene.js 的唯一时间表；shots 的 start/end 由它派生。需要共享事件时，使用配套 `frame-sync-sfx/scripts/timeline.py`，此脚本只需 Python 标准库。两个技能可以相邻安装，也可用实际路径调用，不依赖当前 Agent 名称。

```sh
python <frame-sync-sfx>/scripts/timeline.py --cues <作品>/cues.json --emit <作品>/events.js
python <frame-sync-sfx>/scripts/timeline.py --cues <作品>/cues.json --emit <作品>/events.js --check --shots <作品>/shots.json
```

1. 在 cues.json 的 scenes 写分场时长，关键动作写 scene+at；在 shots 中只连接同名场景并写叙事。
2. scene.js import `SCENES, DURATION` 及关键事件数组；数组的时刻含义明确为“触碰”“开始转向”等。局部缓动允许参数化。
3. 调整时长后重新生成 events；有声时重新合成音轨。生成文件有 cue 哈希，`--check` 拦陈旧文件，音轨旁的报告也带源哈希。
4. 回归一次：在隔离副本把 S01 加长 1 秒，确认 S02 和共享事件都后移 1 秒；原工程保持不动。检查 shots 重复时长没有遗留。

## 需要声音时

先读配套技能 `frame-sync-sfx`（独立安装；相邻目录部署，或按实际路径调用；未安装时告知用户需要它）。它继续承担音频，与画面技能分开，让静音创作不必装科学计算依赖。

```sh
python <frame-sync-sfx>/scripts/synth.py --cues <作品>/cues.json --out <作品>/score.wav --emit <作品>/events.js
# 有已授权本地 BGM 时可选
python <frame-sync-sfx>/scripts/mix.py --sfx <作品>/score.wav --bgm <音乐文件> --out <作品>/final-mix.wav
```

scene.js 通过 audioWav() 读最终 WAV，按主技能 render 命令导出。最终 MP4 用配套 verify 检查，score 参数必须为导出时使用的 WAV。音乐来源、授权和哈希写入项目素材表；外部素材可纳入复现，不混淆“未带外部素材”和“无法复现”。不因为接入动效就自动生成 TTS。

音轨一致性、共享时刻、实际画面动作是三个检查。前两个自动通过后，仍抽关键事件前/当时/后一帧并正常速度播放成片。不要把互相关 0 采样写成“已经证明所有音画同步”。不用机械检测到每段有声来替代试听；有意留白可以保留。
